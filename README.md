# 🏋️‍♂️ Body Check - 몸무게 및 건강 관리 반응형 웹앱

본 프로젝트는 PC와 모바일(iPhone Safari) 환경에 최적화된 반응형 헬스케어 대시보드 웹앱입니다.
모든 건강 기록과 설정은 디바이스 로컬 저장소(`shared_preferences`)에 보관합니다. AI 분석은 로컬 규칙 또는 사용자가 직접 운영하는 Ollama 서버를 사용합니다.

---

## 🌟 MVP 주요 핵심 기능
1. **오늘 체중 및 건강 데이터 입력**: 체중, 체지방률, 허리둘레, 운동기록, 수면시간, 식단상태, 메모 입력 가능
2. **반응형 대시보드 (홈)**: 현재 체중, 목표 체중, 7일 평균, 30일 변화량 및 BMI 상태 실시간 계산 노출
3. **인터랙티브 차트**: 체중 변화선, 7일 평균 점선 및 목표 체중 가이드라인 실시간 시각화 (`fl_chart` 기반)
4. **기록 리스트 및 CRUD**: 저장된 전체 데이터를 날짜순(내림차순) 정렬, 수정 및 확인 질문창이 적용된 삭제 기능 제공
5. **다크 모드 지원**: 슬레이트 다크 테마 적용으로 야간 및 저조도 환경 조작 피로도 감소
6. **로컬 우선 저장**: 건강 기록과 설정을 브라우저 로컬 저장소에 보관

## 🚀 PC 로컬 실행 방법 (VS Code 기준)

1. **프로젝트 열기**:
   VS Code에서 프로젝트 루트 폴더를 엽니다.

2. **패키지 설치**:
   VS Code 터미널(Ctrl + `)을 열고 아래 명령어를 입력하여 필요한 플러그인을 내려받습니다.
   ```bash
   flutter pub get
   ```

3. **로컬 Chrome에서 실행**:
   VS Code의 디버그 패널(F5)을 누르고 런칭 프로필 중 **`Body Check (Chrome)`**을 선택해 가동하거나, 터미널에 아래 명령어를 입력합니다.
   ```bash
   flutter run -d chrome --web-port 8080
   ```
   가동이 끝나면 크롬 브라우저가 열리며 대시보드가 런칭됩니다.

## 📱 아이폰 Safari에서 모바일 앱처럼 접속 및 테스트하는 방법

모바일 기기에서 PC의 로컬 개발 서버에 접속하여 반응형 인터페이스를 점검하고, 홈 화면에 얹어 앱처럼 사용하는 순서입니다.

### 1단계: PC와 아이폰을 동일한 Wi-Fi 네트워크에 연결하기
* PC와 아이폰이 **동일한 유무선 공유기(AP)** 하위의 Wi-Fi 네트워크를 잡고 있어야 합니다.

### 2단계: PC의 로컬 IP 주소 확인하기
* PC의 명령 프롬프트(cmd) 또는 터미널을 열고 아래 명령어를 입력합니다.
  ```cmd
  ipconfig
  ```
* 출력 내용 중 **"무선 LAN 어댑터 Wi-Fi"** 또는 **"이더넷 어댑터"** 항목 아래의 `IPv4 주소`를 찾습니다.
  * 예: `192.168.0.15`

### 3단계: 외부 접속 허용 모드로 개발 서버 가동하기
* 기본 실행 방식은 루프백(`localhost`)으로만 열리므로 외부 기기가 연결할 수 없습니다.
* 모든 인터페이스(`0.0.0.0`) 바인딩 옵션으로 서버를 구동해야 합니다.
* VS Code 디버그 프로필에서 **`Body Check (Mobile Web Server)`**를 선택해 F5를 누르거나, 터미널에 아래와 같이 구동 명령을 입력합니다.
  ```bash
  flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080
  ```
* 서버가 켜지면 외부 기기로부터 오는 통신 포트 `8080`을 열고 대기하게 됩니다.

### 4단계: 아이폰 Safari에서 접속하기
1. 아이폰에서 **Safari 브라우저**를 실행합니다.
2. 주소창에 `http://<PC의 로컬 IP>:8080` 을 입력하여 접속합니다.
   * 예: `http://192.168.0.15:8080`
3. PC 웹 대시보드가 아이폰 화면에 맞춰 깔끔한 1열 카드형 UI 및 모바일 전용 탭바 형태로 자동 반응하는지 확인합니다.

### 5단계: 아이폰 홈 화면에 추가하여 앱처럼 구동하기
1. Safari 브라우저 하단의 **[공유 버튼]** (위로 향한 화살표가 있는 사각형 아이콘)을 누릅니다.
2. 스크롤을 살짝 내려 **[홈 화면에 추가]** 메뉴를 선택합니다.
3. 이름을 **"Body Check"**로 입력한 뒤 우측 상단의 **[추가]**를 누릅니다.
4. 이제 아이폰 바탕화면에 등록된 아이콘을 누르면, 브라우저 상단 주소창이 제거된 풀스크린 PWA 모드로 구동되어 훨씬 쾌적한 네이티브 헬스케어 앱 느낌으로 사용하실 수 있습니다.

* Ollama를 사용하는 경우 사용자가 지정한 Ollama 서버로 분석용 기록이 전송될 수 있습니다.

## GitHub 공개 전 보안 참고

* 프로필 비밀번호/PIN은 서버 계정 인증이 아니라 같은 브라우저 안에서 프로필을 구분하는 로컬 잠금 기능입니다. 다른 서비스에서 사용하는 비밀번호를 입력하지 마세요.
* 브라우저 데이터나 사이트 저장 공간을 삭제하면 프로필, 기록, 사진과 설정이 모두 사라질 수 있습니다. 중요한 데이터는 별도로 보관하세요.
* `setup_ollama.bat`은 기본적으로 `localhost:8080`과 `127.0.0.1:8080`만 허용합니다. `OLLAMA_ORIGINS=*`는 사용하지 마세요.
* GitHub Pages에서 Ollama를 사용할 때는 정확한 Pages 출처만 허용하세요. Ollama의 11434 포트를 인터넷에 직접 노출하지 마세요.
* GitHub Pages의 HTTPS 페이지에서 HTTP Ollama 서버 연결은 브라우저 정책으로 차단될 수 있습니다. 이 경우 로컬에서 앱을 실행하거나 인증이 적용된 HTTPS 프록시가 필요합니다.

## GitHub Pages 배포

이 저장소는 `.github/workflows/deploy-pages.yml`을 통해 Public 저장소의 `main` 브랜치가 업데이트될 때 Flutter Web을 자동 빌드하고 GitHub Pages에 배포합니다. Private 상태에서는 배포 작업을 건너뜁니다.

1. GitHub 저장소의 **Settings → Pages**로 이동합니다.
2. **Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. `main` 브랜치에 push합니다.
4. 저장소의 **Actions** 탭에서 `Deploy Flutter Web to GitHub Pages`가 성공하는지 확인합니다.
5. 배포 주소는 일반 저장소의 경우 `https://사용자명.github.io/저장소명/`입니다.

로컬에서 Pages 경로를 확인하려면 다음처럼 빌드할 수 있습니다.

```bash
flutter build web --release --base-href /body-check/
```
